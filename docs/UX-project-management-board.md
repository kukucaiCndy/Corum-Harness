## 0. 核心交互诉求（用户定调）

> 用户在左侧会话栏点击「计划 / 需求 / 任务 / 版本 / 问题 / 文档」任一管理项 → **自动隐藏除「会话列表」和「Agent 对话区」之外的所有区域** → 在腾出的整片空间插入并展示对应的项目管理看板。会话列表与对话区始终保留，用户可边对话边看板、指挥 Agent 操作看板。

## 1. 区域切换的状态模型（Workspace View Mode）

这是**工作区视图模式切换**，不是路由跳转——同一会话上下文下的布局态切换。

```
开发态 (Dev Mode)
  └─ 点击左侧「管理」段任一项 ──▶ 管理态 (Manage Mode)
                                     │ 子态: activeBoard ∈ {计划|需求|任务|版本|问题|文档}
                                     │ （切子态不退回开发态，原地换看板内容）
  ◀─ 返回路径（三条，见 §5）────────┘
```

- **切换幂等**：已在管理态时点另一管理项 = 只换 `activeBoard`，布局不动。
- **记忆策略**：管理态记录进入前的开发态布局快照（各列宽度/终端开合），返回时原样恢复；再次进入管理态恢复上次的 `activeBoard` 与选中实体。

## 2. 触发的空间行为（用户拍板：占整片）

**保留**：会话列表、Agent 对话区（对话区宽度不变）。
**隐藏**：编辑器、资源管理器、底部终端，整片折叠。
**看板位置**：占据原「编辑器 + 资源管理器」的**整片右侧空间**，并吸收终端折叠后释放的纵向高度。

```
【开发态】                                    【管理态】
┌────┬────────┬──────────┬─────┐           ┌────┬────────┬────────────────────┐
│会话 │ Agent  │  编辑器   │资源 │           │会话 │ Agent  │  管理看板           │
│列表 │ 对话区  │          │管理 │    →     │列表 │ 对话区  │ ┌────────────────┐ │
│    │        │          │器   │           │(可  │(保持)  │ │计划|需求|任务|版本|问题|文档│
│管理:│        │          │     │           │切换)│        │ ├────────────────┤ │
│▸计划│        │          │     │           │    │        │ │  看板主视图      │ │
│ 需求│        │          │     │           │    │        │ │  (+详情抽屉)    │ │
│ 任务│        │          │     │           │    │        │ └────────────────┘ │
│ 版本│        │          │     │           │    │        │  [← 返回开发]      │ │
│ 问题│        │          │     │           │    │        │                    │

├────┴────────┴──────────┴─────┤           ├────┴────────┴────────────────────┤
│           终端                │           │        （终端折叠隐藏）            │
└──────────────────────────────┘           └──────────────────────────────────┘
```

## 3. 管理段菜单（用户拍板：6 项）

| 菜单项 | 对应实体 | 视图核心价值 |
|---|---|---|
| **计划** | Plan / PlanStage | 项目节奏一目了然（阶段时间盒） |
| **需求** | Requirement | 主链路进度总览（需求→任务→BUG→完成度） |
| **任务** | Task | 执行推进器（状态流转） |
| **版本** | Release | 交付物与质量对照（关联 BUG） |
| **问题** | BUG | 质量闭环（缺陷生命周期） |
| **文档** | Doc | 知识沉淀唯一入口（唯一性约束） |

> 「计划 vs 需求」：计划答"什么时候交付什么"，需求答"每个需求走到哪一步"。「问题」面向用户语言，视图内即 BUG。

## 4. 各看板视图拆解（统一三段式骨架）

统一骨架：**顶栏（面包屑 Tab + 筛选 + 主操作"新建"）→ 分组主体 → 右侧详情抽屉（选中滑出）**。所有实体对 Agent 暴露为可读写上下文，对人可点选。

### 4.1 计划视图
- **主体**：按 Plan 分组的泳道列表，行内为 PlanStage。
- **字段**：阶段名、周期、状态（未开始/进行中/已完成）、关联需求数、完成进度条。
- **主操作**：新建计划、@Agent 生成/调整计划、编辑阶段。
- **详情抽屉**：阶段下需求与任务分布。

### 4.2 需求视图（主线心脏）
- **主体**：按阶段/状态分组的列表。
- **字段**：需求名、所属阶段、状态（submitted/in_dev/dev_done/verifying/finished）、任务完成度(n/m)、阻断级 BUG 数（红标）。
- **主操作**：PD 新建/编辑；**PM 点「裁决 finished」**（仅当任务全完成且阻断/严重 BUG 清零，否则置灰并提示缺口）。
- **详情抽屉**：需求下的任务 / BUG / 文档三 Tab。

### 4.3 任务视图
- **主体**：四列看板（todo / doing / dev_done / completed）；P0 可先用列表+状态筛选。
- **字段**：任务名、负责人(assignee)、所属需求、优先级、关联版本号。
- **主操作**：TL 拆任务/指派、拖拽改状态（todo→doing→dev_done）、**PM 在 dev_done 卡片点「裁决完成」**、一键"派给 Agent"。
- **详情抽屉**：任务描述、验收标准、关联版本、变更记录。

### 4.4 版本视图
- **主体**：列表。
- **字段**：版本号(name)、对应 ref(commit/tag)、提交人(Dev/PM)、提交时间、关联任务、引入 BUG 数。
- **主操作**：查看变更说明、关联 BUG、下载。
- **详情抽屉**：变更摘要 + BUG 清单。

### 4.5 问题（BUG）视图
- **主体**：列表 + 状态/严重度/需求筛选 Tab。
- **字段**：标题、严重级（阻断/严重/一般/轻微）、状态、指派人、关联版本、创建人(QA)。
- **主操作（按状态出现）**：处理(open→processing)、fixed/rejected/转交(processing，Dev)、**验收关闭(pending_verify→closed，仅 QA)**。
- **详情抽屉**：复现描述、处理流(transferHistory)、验收备注。

### 4.6 文档视图
- **主体**：按类型/关联需求分组的列表。
- **字段**：文档名、类型(PRD/技术方案/ADR/记忆)、所属需求、最后更新(Agent/人)、更新时间。
- **唯一性**：同需求同类型仅一份，重复创建自动合并/提示。
- **主操作**：新建、在编辑器打开（自动退回开发态）。
- **详情**：内嵌阅读器。

## 5. 选中联动（用户拍板：详情抽屉 + 抽屉内"注入对话"按钮）

- **选中实体 → 详情抽屉**：点击看板中任一实体，从看板右缘滑出 **360px 详情抽屉**（字段 + 操作按钮 + 相关对话入口），不遮对话区，可关闭。
- **注入对话（按需，非自动）**：详情抽屉内提供**「注入对话」按钮**——点击后把该实体以 chip 形式注入对话区输入框上方（如 `#任务-128`），Agent 后续对话自动携带该实体上下文；chip 可移除。**兼顾了"只观看"与"按需喂给 Agent"两种诉求**。
- **Agent 操作 → 实时反馈**：用户在对话中说"把任务-128 标完成"，Agent 调用工具成功后，看板对应卡片即时动画迁移列 + 短暂高亮（1.5s），对话区回执操作结果卡片。看板数据源与 Agent 工具层共享同一 store，天然双向同步；失败时卡片抖动回弹并在对话中报错。

## 6. 导航 / 面包屑 / 返回

- **面包屑 Tab**：看板顶栏左侧显示 `管理 / 任务`（当前项高亮），六个管理项以 Tab 并列，点击即切子态。
- **返回开发的三个出口**：① 面包屑旁常驻「← 返回开发」按钮；② 左侧栏"管理"段再次点击当前选中项（toggle）；③ 快捷键 `Cmd/Ctrl+Shift+M`。语义统一：回到快照恢复的开发态。
- **左侧栏选中态**：管理项被点中后整行高亮 + 左侧 2px 强调色指示条，与会话选中态视觉区分；管理态下允许"管理项高亮 + 某会话高亮"双选中并存。
- **会话列表在管理态**：功能完整保留（可切换/新建会话）。看板是**项目级**而非会话级视图，切会话只换对话上下文，**看板不跟随切换、不重置选中实体**，避免"切会话看板乱跳"。多项目（P1+）由看板顶栏项目切换器显式控制，与会话解耦。

## 7. 角色操作落点（与 PRD §4 权限一致）

- **PM**：需求视图裁决 finished、任务视图裁决 completed——均弹二次确认（Agent 代执行同样需人确认）。
- **PD**：计划/需求视图的创建与编辑。
- **TL**：任务视图拆任务、指派。
- **Dev**：任务视图改 doing/dev_done、提交版本；BUG 视图 fixed/rejected/转交。
- **QA**：BUG 视图建 BUG、pending_verify→closed（唯一关闭人）。

状态机内流转（doing→dev_done）可直接操作；**所有"裁决/关闭/驳回"类动作必须走人确认**，看板上体现为确认弹窗，不静默完成。

## 8. 空态与冷启动

统一空态结构：**一句话价值说明 + 主 CTA + 次 CTA**。

| 视图 | 说明 | 主 CTA | 次 CTA |
|---|---|---|---|
| 计划 | 还没有计划，让 PM/PD 帮你规划 | @Agent 生成首个计划 | 手动创建 |
| 需求 | 还没有需求 | @Agent 录入需求 | 手动创建 |
| 任务 | 还没有任务，让 TL 帮你拆解 | @Agent 拆解需求为任务 | 手动创建 |
| 版本 | 还没有版本 | @Dev 提交首个版本 | — |
| 问题 | 暂无问题 | @QA 创建首个 BUG | — |
| 文档 | 还没有文档，让 Agent 生成 PRD 骨架 | @Agent 生成 PRD 骨架 | 手动创建 |

CTA 点击后自动把指令填进对话区，实现"**看板引导、对话执行**"。

## 9. 看板 × 对话区联动场景

1. **上下文注入**：用户在需求详情抽屉点「注入对话」，输入"@Agent 把这个需求的任务补齐"——需求 ID/摘要自动喂给 Agent，产出后看板即时刷新。
2. **看板指挥执行**：用户看到 dev_done 任务，在对话区说"PM 裁决 T-102"，Agent 调裁决接口，结果（需人确认）以卡片回到对话区，PM 一键确认后看板列变更。
3. **反向溯源**：对话区 Agent 汇报"已提交版本 v0.3，修复 B-201"，版本号/BUG 号渲染为可点链接，点击跳转对应看板详情抽屉，对话与看板互相回链。

## 10. P0 视图取舍（评审收敛）

- **P0 必做**：计划、需求、任务、BUG 四视图（主链路闭环）+ 文档视图（仅"唯一性三件套"：按需求+类型唯一、合并提示、内嵌阅读）+ 空态引导 + 详情抽屉与「注入对话」按钮 + 区域切换机制。
- **P0 简化**：任务视图先用列表+状态筛选代替四列拖拽看板；BUG 视图不做转交历史可视化。
- **P1**：版本视图、四列看板拖拽、看板趋势图/燃尽、完成度进度条增强、变更时间线、转交历史可视化。

## 11. 给开发的落地提示

- 布局态实现为 IDE-shell 的 **region visibility 开关** + 一个 `ManageBoard` 覆盖层，挂载在「编辑器 + 资源管理器」合并区域。
- `activeBoard`、选中实体、详情抽屉开合、布局快照放入**全局 workspace store**；Agent 工具与看板组件读写同源（与 `ctx.project` 数据层打通）。
- 区域显隐可复用现有 `setLeafHidden` / `SET_REGION_HIDDEN_EVENT` 机制（插件中心视图管理已用），管理态=批量隐藏指定 leaf + 挂载 ManageBoard。
