## 1. 产品定位

corum Agent OS 是一个**桌面端 AI 编码/对话工作台**。设计目标是把「聊天」和「代码」统一进一个 **IDE（集成开发环境）心智**：

- **任务/项目 = 双模式侧栏**：左侧侧栏是工作的「入口」——默认任务模式（新建会话 + 会话列表），可一键切换项目模式（打开/新建项目、项目详情：团队 Agent / 管理维度 / 会话分组）。
- **对话 = 常驻工作区**：Agent 对话区是中列常驻工作区，不再是编辑器里的一个 tab。
- **代码 = 常驻编辑器**：Monaco 编辑器是右侧常驻编辑区，与对话区并列。

一句话：**用户感觉自己在用一个「会聊天的 IDE」，而不是一个「能看代码的聊天窗」。**

## 2. 设计原则（贯穿全部页面）

1. **IDE 心智优先**：布局、密度、交互习惯对齐成熟 IDE（VS Code / JetBrains / Cursor），不发明新范式。
2. **任务/项目双模式**：侧栏内置「任务模式（默认）/ 项目模式」两种视图，brand 右侧 mode-switch 一键切换；任务模式 = 会话列表，项目模式 = 项目详情（团队 Agent、管理维度、会话分组收拢在项目详情内），而非多个割裂的面板。
3. **操作收拢**：会话的「重命名 / 归档 / 删除」收进项目导航会话条目的右键菜单，与 IDE 的右键菜单习惯一致。
4. **单一 active 会话**：同时只有一个会话在前台（对话区一次渲染一个会话），多会话靠项目导航切换，不做多窗格并行渲染。
5. **语义化主题 token**：所有颜色走语义 token（背景层 / 文字层级 / 品牌色 / 状态色），**深浅主题切换只换 token 值，不换组件结构**。
6. **信息密度适中**：桌面端偏「紧凑专业」，留白克制，但状态信息（运行中 / 等待 / 完成）要一眼可辨。
7. **图标统一 Lucide**：全局图标走 Lucide 已验证列表，禁止 emoji 充当功能图标；文件树图标按类型着色（见 §4.4）。

## 4. 逐区交互规格

### 4.1 侧栏（左列 280px，任务 / 项目双模式）

> **2026-08-25 改造**：由「项目导航」升级为「任务 / 项目」双模式侧栏，**默认任务模式**；侧边栏为固定常驻区，**不可关闭**（无 region-actions 关闭按钮）。

**品牌横幅 + 模式切换（顶部固定）**：

- 品牌横幅（深/浅各一）右侧内嵌 **mode-switch** 分段切换器：「项目 / 任务」两段，复用 `scope-switch` 样式（激活段 `$brand-primary` + `$label-on-brand`，idle 透明 + `$label-secondary`，11/600）。
- 点击切换时，brand 以下内容整体**反转动画**（rotateY 翻转，参数见 DESIGN.md §7.10）；切换按钮激活段随之滑动。

**任务模式（默认）**：

1. **新建会话**：主按钮（`$brand-primary`，＋ 新建会话）。
2. **会话列表**：扁平会话行（状态点 + 标题 + 时间），首个为选中态（`glass-2` + 光边）；无会话时显示空态引导（暂无会话 · 点击「新建会话」开始对话）。

- 会话条目右键菜单：重命名 / 归档 / 删除（见 §8）。

**项目模式（点击切换后）**：

1. **空态（未打开项目）**：顶部「打开项目」主按钮（与任务模式「新建会话」同位同款，`$brand-primary`；**空目录即新建项目**，不再单独提供「新建项目」按钮）+ 空态提示（打开项目开始协作 · 空目录即新建）。
   - **「打开项目」分流**：已有项目 → 自动加载进入项目详情；**空目录 → 进入「项目创建向导」**（见下）。
2. **项目详情（打开项目后）**：
   - 项目头：当前项目卡（项目名 / 成员数 / 状态 + **关闭项目 ×**）。
   - 管理段：计划 / 任务 / 事件 / 文档 / 问题 五个维度，各带计数与语义图标（Lucide）。
   - 团队段：Agent 成员组（chevron 折叠 + 状态点 + 名称 + 会话计数），组下挂该 Agent 的会话列表（可折叠，未来可关联任务）。

**交互流**：`默认任务模式（会话列表 ⇄ 无会话空态）⇄ 点击切换 → 项目模式（空态 → 打开项目 → 项目详情 · × 关闭项目）`
**状态**：任务模式·会话列表 / 任务模式·空态 / 项目模式·空态 / 项目模式·项目详情（见 L2 页面清单）。

**项目创建向导**（点「打开项目」且目录为空时触发，模态弹窗，见 L2「项目创建向导」两页：主流程 ①②③ + 触发与补充 ⓪②′④）：

⓪ **打开项目 · 目录选择**（点「打开项目」后）：最近项目列表 + 「选择文件夹…」；分支——**已有项目目录 → 自动加载**；**空目录 → 进入创建向导**。
1. **① 基本信息 · 项目命名**：输入项目名称 + 展示已选目录（附「空目录」徽标，提示将作为新项目创建）；底部 [取消] [下一步 →]；顶部步骤条 ①基本信息 —— ②团队与成员。
2. **② 团队与成员**：选取团队（团队下拉「矩道前端组 · 5 名成员」）；两种加入方式——**整个团队加入**（全部成员）/ **部分成员加入**（成员勾选列表，可勾选任意成员）；[上一步] [创建项目]。
   - **②′ 添加成员浮层**：点「+ 添加成员」弹出成员选择器（搜索 + 成员列表（Agent/自定义）逐项 [＋]/[✓]，可单独添加非团队成员）。
3. **③ 创建完成**：成功态（check）+ 项目名 + 已加入成员数；[进入项目]。
   - **④ 创建中加载**（[创建项目] 后）：loader + 进度步骤（创建项目仓库 ✓ / 配置团队 · 3 名成员 loading / 初始化会话）→ 完成后进入项目详情。

## 5. 区域卡片与操作（RegionCard 基座）

每个区域是一张统一玻璃卡片，对应设计稿组件 **region-card(xQylw) / region-actions(knD1D)**。

- **拖出为浮动窗**：在区域内任意**非交互处**（非按钮 / 输入框 / 链接 / 选中文字）**长按鼠标左键并拖拽出窗口**即可脱出；组件交互与文字选择不受影响。**无独立「拖出」按钮**。
- **关闭按钮**：
  - 有头部工具组的区域（对话区、资源管理器）：并入其工具组最右，与该组按钮同规格（30×30 / 20×20）。
  - 无头部的区域（编辑器）：右上角 30×30 悬浮按钮。
  - **① 侧栏（双模式）不可关闭**：固定常驻左列，无关闭按钮（2026-08-25 移除 region-actions）。

## 8. 会话管理动词（收拢到会话条目右键菜单）

> 会话动词收进项目导航会话条目的右键菜单，与 IDE 右键菜单习惯一致。

| 动词 | 触发方式 | 行为 | 确认 | 状态反馈 |
|---|---|---|---|---|
| 重命名 | 右键菜单 | 行内输入或弹窗改标题 | 无 | 标题即时更新 |
| 归档 | 右键菜单 | 移入归档集（隐藏，不删） | 无 | 行从列表消失 |
| **删除** | 右键菜单 | 原生「确认删除」对话框 → 物理删除 | **强制**（不可逆） | 删除中 → 成功/失败；成功后列表实时消失 |

- **分叉（fork）**：入口在对话区头部 git-branch 按钮，从当前会话派生分叉会话并打开。
- **保存日志**：原生「保存」对话框 → 写 ZIP，结果弹窗（路径/错误），见 L4。
- **删除的交互红线**：必须经过原生确认对话框（`showMessageBox`，默认「取消」），删除中显示进行态，失败保留会话并提示重试。
- **删除当前会话**：删除成功后，自动切换到最近会话或空态，不留僵尸选中。
- **入口唯一性**：对话区头部不再有「保存/删除」按钮（会话自动持久化，save 按钮已移除）；「导入会话日志」保留在设置页。

## 9. 主题系统（深色 / 浅色，必须）

> **硬性要求：所有设计稿必须交付「深色」和「浅色」两套，缺一不可。**

- **机制**：语义化 CSS token（沿用官方 `--dsw-alias-*` 体系），组件只引用 token，不写死颜色。
- **切换**：顶部标题栏设置 → 外观；三态 `light / dark / system`（跟随系统）。（原状态栏快捷切换已随状态栏移除。）
- **必须覆盖的 token 类别**（设计稿需定义两套 hex 值）：
  - 背景层：`bg-base` / `bg-layer-1/2/3` / `bg-overlay` / `bg-skeleton`
  - 文字层级：`label-primary` / `label-secondary` / `label-tertiary` / `label-dimmed`
  - 品牌色：`brand-primary` / `brand-text`（+ 对应 invert）
  - 状态色：`state-error` / `state-success` / `state-warn`（各 primary/secondary）
  - 交互态：`interactive-bg-hover` / `interactive-bg-active` / 边框 `border-l1/l2/l3`
  - 特殊：`markdown-code-block` / `markdown-inline-code`（代码块在深浅色下对比度要够）
- **深浅色对比度基线**：正文 ≥ 4.5:1，大号文字 ≥ 3:1；代码块背景与正文背景要有明显层次。
- **Monaco 主题**：编辑器用 `vs-dark`（深色）/ `vs` 或 `vs-light`（浅色），与全局主题联动。
