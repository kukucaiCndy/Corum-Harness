## 1. 产品定位

corum Agent OS 是一个**桌面端 AI 编码/对话工作台**。设计目标是把「聊天」和「代码」统一进一个 **IDE（集成开发环境）心智**：

- **项目 = 项目导航**：左侧项目导航是工作的「入口」——项目、团队 Agent、管理维度、会话分组都收在这一列。
- **对话 = 常驻工作区**：Agent 对话区是中列常驻工作区，不再是编辑器里的一个 tab。
- **代码 = 常驻编辑器**：Monaco 编辑器是右侧常驻编辑区，与对话区并列。

一句话：**用户感觉自己在用一个「会聊天的 IDE」，而不是一个「能看代码的聊天窗」。**

## 2. 设计原则（贯穿全部页面）

1. **IDE 心智优先**：布局、密度、交互习惯对齐成熟 IDE（VS Code / JetBrains / Cursor），不发明新范式。
2. **项目与会话融合**：项目、团队 Agent、会话分组共享左侧项目导航一列，而非多个割裂的面板。
3. **操作收拢**：会话的「重命名 / 归档 / 删除」收进项目导航会话条目的右键菜单，与 IDE 的右键菜单习惯一致。
4. **单一 active 会话**：同时只有一个会话在前台（对话区一次渲染一个会话），多会话靠项目导航切换，不做多窗格并行渲染。
5. **语义化主题 token**：所有颜色走语义 token（背景层 / 文字层级 / 品牌色 / 状态色），**深浅主题切换只换 token 值，不换组件结构**。
6. **信息密度适中**：桌面端偏「紧凑专业」，留白克制，但状态信息（运行中 / 等待 / 完成）要一眼可辨。
7. **图标统一 Lucide**：全局图标走 Lucide 已验证列表，禁止 emoji 充当功能图标；文件树图标按类型着色（见 §4.4）。

## 4. 逐区交互规格

### 4.1 项目导航（左列 280px）

由原「会话列表」升级为「项目导航」，自上而下：

1. **品牌横幅**：品牌区横幅图片（深/浅各一）。
2. **新建项目 / 打开项目**：两个操作按钮。
3. **「项目」标题行 + 项目选择器**：当前项目卡，显示项目名 / 成员数 / 任务数；点击展开项目列表切换项目。
4. **管理段**：计划 / 任务 / 事件 / 文档 / 问题 五个维度，各带计数与语义图标（Lucide），为轻量项目管理预留。
5. **团队段（团队+会话合并）**：段组头单行——左侧「团队」标题 + 添加 Agent 按钮，右侧搜索框。每个 Agent 成员是一组，**成员行即组头**（chevron 折叠 + 状态点 + 名称 + 角色标签 + 会话计数），成员组下挂该 Agent 的会话列表（可折叠，未来可关联任务）。Agent 由创造模式生成、可自定义、加入团队。

> 说明：团队与会话合并为一段——成员名单不再重复出现，会话直接挂在成员下，归属关系一目了然。

- **会话条目右键菜单**：重命名 / 归档 / 删除（见 §8）。
- **状态**：正常态 / 选择器展开 / 会话分组折叠 / 空态 + 骨架屏（见 L2 页面清单）。

### 4.2 Agent 对话区（中列 flex）

- **Convo Header**：左侧「对话 / 轨迹」两个选项卡（原独立 View Tabs 行已并入头部）；右侧三个 30×30 按钮——git-branch（分叉）/ chart-column（统计）/ ×（关闭）。
  - 已删除：原状态点 / 标题 / 面包屑；save 按钮（会话自动持久化）；monitor 按钮（拖出已改为长按拖拽，见 §5）。
  - 统计按钮点击弹出 **status 浮层**（替代原常显 Session Stats 卡片）：run-chip + 轮次 / 时长 / 工具耗时 / token 上下行 / 费用。
- **Chat Flow 对话流**：消息流 + **子 Agent 任务进度卡片**（见 §6）+ 轨迹时间线 + 步骤详情。
- **文件更改审查卡**：展示 Agent 产生的文件改动，供审查。
- **Chat Input 输入框**（双行，详见 §7）：
  - 上行：多行输入区（placeholder「描述一个开发任务，用 @ 添加上下文，/ 使用命令」）+ 右上 sparkle。
  - 下行工具条：左——＋添加上下文 / 🛡授权方式 / @Agent 选择；右——上下文统计（gauge + 百分比）/ 模型选择 / 语音 / 发送。

### 4.3 编辑器区（430px）

- **Editor Tabs**：文件 tab，显示文件名 + 未保存 dirty 圆点；点击切换文件；关闭文件（未保存需确认，见 L4 未保存确认弹窗）。
- **面包屑**：当前文件路径。
- **Monaco**：常驻编辑器，主题与全局深浅色联动。
- **Editor Status**：编辑器状态行。

### 4.4 资源管理器（210px）

VS Code 风格文件树：

- **根标题栏**：根目录名 + 五个 20×20 工具钮——新建文件 / 新建文件夹 / 刷新 / 折叠全部 / 关闭。
- **树体**：目录展开/收起；文件按类型着色图标（`.ts` 紫 / `.md` 绿 / `.json` 黄 / `.yml` 粉 / `.env` 灰）；缩进参考线；选中态。
- 双击文件在编辑器区打开。

### 4.5 终端

- 终端是网格普通叶子（与其他区域同构）：默认位于对话区下方（同列同宽，150px），可调宽 / 调高 / 可拖到任意位置与其他区域自由组合，可关闭。
- **仅保留「终端」**，移除原待办 / 队列 tab。

### 4.6 ~~状态栏（34px）~~（已移除，2026-08-21）

> 状态栏整体移除：连接状态 / 当前项目 / 当前模型不再在底部展示；原「状态栏详情浮层」一并作废。后续如需呈现连接/项目/模型，将以其他形式（如标题栏、设置页内）提供。

## 5. 区域卡片与操作（RegionCard 基座）

每个区域是一张统一玻璃卡片，对应设计稿组件 **region-card(xQylw) / region-actions(knD1D)**。

- **拖出为浮动窗**：在区域内任意**非交互处**（非按钮 / 输入框 / 链接 / 选中文字）**长按鼠标左键并拖拽出窗口**即可脱出；组件交互与文字选择不受影响。**无独立「拖出」按钮**。
- **关闭按钮**：
  - 有头部工具组的区域（对话区、资源管理器）：并入其工具组最右，与该组按钮同规格（30×30 / 20×20）。
  - 无头部的区域（项目导航、编辑器）：右上角 30×30 悬浮按钮。

## 6. 子 Agent 任务进度卡片（subagent-card）

主 Agent 召唤子 Agent 时，在对话流中就地插入进度卡片：

- **显示**：子 Agent 头像 / 名称 / 任务 / run-chip 状态 / 进度条 / 当前步骤。
- **两个交互**：
  1. **chevron**：就地展开 / 收起子任务步骤详情。
  2. **arrow-right**：把当前对话切换到该子 Agent 的会话。

## 8. 会话管理动词（收拢到会话条目右键菜单）

> 会话动词收进项目导航会话条目的右键菜单，与 IDE 右键菜单习惯一致。

| 动词 | 触发方式 | 行为 | 确认 | 状态反馈 |
|---|---|---|---|---|
| 重命名 | 右键菜单 | 行内输入或弹窗改标题 | 无 | 标题即时更新 |
| 归档 | 右键菜单 | 移入归档集（隐藏，不删） | 无 | 行从列表消失 |
| **删除** | 右键菜单 | 原生「确认删除」对话框 → 物理删除 | **强制**（不可逆） | 删除中 → 成功/失败；成功后列表实时消失 |

- **分叉（fork）**：入口在对话区头部 git-branch 按钮，从当前会话派生分叉会话并打开。
- **保存日志**：原生「保存」对话框 → 写 ZIP，结果弹窗（路径/错误），见 L4。
- **删除的交互红线**：必须经过原生确认对话框（`showMessageBox`，默认「取消」），删除中显示进行态，失败保留会话并提示重试。
- **删除当前会话**：删除成功后，自动切换到最近会话或空态，不留僵尸选中。
- **入口唯一性**：对话区头部不再有「保存/删除」按钮（会话自动持久化，save 按钮已移除）；「导入会话日志」保留在设置页。

## 9. 主题系统（深色 / 浅色，必须）

> **硬性要求：所有设计稿必须交付「深色」和「浅色」两套，缺一不可。**

- **机制**：语义化 CSS token（沿用官方 `--dsw-alias-*` 体系），组件只引用 token，不写死颜色。
- **切换**：顶部标题栏设置 → 外观；三态 `light / dark / system`（跟随系统）。（原状态栏快捷切换已随状态栏移除。）
- **必须覆盖的 token 类别**（设计稿需定义两套 hex 值）：
  - 背景层：`bg-base` / `bg-layer-1/2/3` / `bg-overlay` / `bg-skeleton`
  - 文字层级：`label-primary` / `label-secondary` / `label-tertiary` / `label-dimmed`
  - 品牌色：`brand-primary` / `brand-text`（+ 对应 invert）
  - 状态色：`state-error` / `state-success` / `state-warn`（各 primary/secondary）
  - 交互态：`interactive-bg-hover` / `interactive-bg-active` / 边框 `border-l1/l2/l3`
  - 特殊：`markdown-code-block` / `markdown-inline-code`（代码块在深浅色下对比度要够）
- **深浅色对比度基线**：正文 ≥ 4.5:1，大号文字 ≥ 3:1；代码块背景与正文背景要有明显层次。
- **Monaco 主题**：编辑器用 `vs-dark`（深色）/ `vs` 或 `vs-light`（浅色），与全局主题联动。

## 11. 状态清单（每个页面需覆盖）

| 状态 | 说明 | 必现页面 |
|---|---|---|
| 正常态 | 有数据、可交互 | 全部 |
| 加载态 | 骨架屏 / 转圈 | 项目导航会话段、文件树、编辑器 |
| 空态 | 无数据引导 | 空态、会话列表空、文件树空 |
| 错误态 | 连接失败 / 操作失败 | 状态栏、删除失败、保存失败 |
| 运行态 | 会话运行中 / 等待用户 | 会话条目状态点、subagent-card run-chip |
| 边缘态 | 长标题截断、长列表滚动、深色下代码块对比 | 会话分组、文件树、编辑器 |

## 12. 设计交付物要求

1. **双主题**：深色 + 浅色各一套（§9），或一套 + 明确 token 映射表（推荐后者）。
2. **`.pen` 文件**：demo.pen（样图）+ design.pen（正式稿），遵循 pencil-design SOP。
3. **素材**：图标统一走 Lucide 已验证列表（管理段五维度各有语义图标；文件树按类型着色）；或 AI 生图 + 去背景；禁止 emoji。
4. **覆盖 L1–L4**：先出 L1 主界面总览（定全局观感），再逐页细化。
5. **交互标注**：长按拖出、右键菜单、浮层弹出、子 Agent 卡展开/切换、主题切换等关键交互需标注行为。
