> 本文档是**设计 Agent 的输入**：拿到它即可直接进入 pencil-design SOP 第 6 步（生成设计执行方案）和第 7 步（正式设计），无需再翻代码。

## 1. 产品定位

corum Agent OS 是一个**桌面端 AI 编码/对话工作台**。设计目标是把「聊天」和「代码」统一进一个 **IDE（集成开发环境）心智**：

- **会话 = 编辑器 tab**：一个会话就是一个工作单元，像 VS Code 的 tab 一样打开、切换、关闭。
- **项目 = 资源管理器**：文件树、workspace、会话列表在左侧，是工作的「入口」。
- **代码 = 常驻编辑器**：Monaco 编辑器不再是聊天里的一个 tab，而是右侧常驻的编辑区。

一句话：**用户感觉自己在用一个「会聊天的 IDE」，而不是一个「能看代码的聊天窗」。**

---

## 2. 设计原则（贯穿全部页面）

1. **IDE 心智优先**：布局、密度、交互习惯对齐成熟 IDE（VS Code / JetBrains / Cursor），不发明新范式。
2. **会话与项目融合**：会话和文件树共享左侧 Explorer，通过「活动栏」切换视角，而非两个割裂的面板。
3. **操作收拢**：会话的「重命名 / 分支 / 归档 / 保存日志 / 删除」全部收进会话列表条目的上下文菜单，与 IDE 的右键菜单习惯一致。
4. **单一 active 会话**：同时只有一个会话在前台（对应一个 active editor），多会话靠 tab 切换，不做多窗格并行渲染。
5. **语义化主题 token**：所有颜色走语义 token（背景层 / 文字层级 / 品牌色 / 状态色），**深浅主题切换只换 token 值，不换组件结构**。
6. **信息密度适中**：桌面端偏「紧凑专业」，留白克制，但状态信息（运行中 / 等待 / 完成）要一眼可辨。

│         │                                                  │                     │
├─────────┼──────────────────────────────────────────────────┴─────────────────────┤
│  ③ 主侧栏（Explorer：文件树 + 会话/项目列表）                                        │

| 区 | 名称 | 角色 | 承载内容 | 设计来源 |
|---|---|---|---|---|
| ① | 活动栏（activity-bar） | 视角切换 | Explorer / 编辑器 / 终端 / 待办 / 队列 的图标切换 | 新增（`@corum/corum-layout`） |
| ② | 编辑器区（editor-group） | 主工作区 | 会话 tab + 文件 tab + 会话视图 + Monaco | fork `ui-layout` + `ui-conversation` + 已有 Monaco |
| ③ | 主侧栏（Explorer） | 入口 | 文件树 + 会话/项目列表（含右键菜单） | fork `ui-workspace` |
| ④ | 次侧栏（secondary-panel） | 辅助 | 详情 / 轨迹 / 工具输出 | 复用官方 `details` slot |
| ⑤ | 底部面板（bottom-panel） | 辅助 | 终端 / 待办 / 队列 | 复用官方 dock |

## 4. 逐区交互规格

### 4.1 活动栏（activity-bar）

- **形态**：56px 竖条，图标纵向排列，顶部 logo / 底部设置齿轮。
- **行为**：点击图标 → 对应面板在主侧栏 / 底部 / 编辑器区之间切换显隐；当前激活图标高亮。
- **条目**（自上而下）：
  1. **Explorer**（文件树 + 会话，默认激活）
  2. **编辑器**（编辑器区聚焦 / 会话 tab 概览）
  3. **终端**（底部面板 — 终端）
  4. **待办**（底部面板 — 待办）
  5. **队列**（底部面板 — 队列）
  6. **设置**（底部固定）
- **状态**：图标带小圆点提示（如队列有待处理、终端有输出）。

### 4.2 主侧栏 Explorer（文件树 + 会话/项目）

这是「会话与项目融合」的核心区域。**两种视图，通过活动栏或分段开关切换**：

**视图 A：会话/项目列表（默认）** — 复用 fork 后的官方 `ui-workspace`
- workspace 分组 + 会话列表，支持搜索、拖拽排序、分组/扁平切换。
- **会话条目右键菜单**（核心，§5 详述）：重命名 / 分支 / 归档 / 保存日志 / 删除。
- 会话状态：运行中（实心点）、等待用户（琥珀点）、完成未读（绿点）、空闲（灰点）。

**视图 B：文件树** — 新增
- 树形文件浏览，展开/折叠目录，双击文件在编辑器区打开。
- 顶部面包屑显示当前 workspace 路径。
- 右键菜单：新建文件/文件夹、重命名、删除（走 shell host 文件桥）。

> 融合点：Explorer 顶部分段开关「项目 / 会话」，或在活动栏再拆两个图标。**推荐方案：活动栏拆「资源管理器（文件树）」和「会话」两个图标**，避免一个面板内塞两套心智。

### 4.3 编辑器区（editor-group）

- **tab 栏**（顶部）：一组 tab，**会话 tab 与文件 tab 可在同一栏，也可分两行/两个区段**。
  - **推荐方案**：tab 栏分左右两段——左侧「会话 tab」，右侧「文件 tab」；或统一 tab 栏用图标区分会话/文件。
  - 会话 tab：显示会话标题 + 运行态圆点；点击切换 active 会话；关闭 = 从 tab 集合移除（**不删除会话**）；「+」新建会话。
  - 文件 tab：显示文件名 + 未保存 dirty 圆点；点击切换文件；关闭 = 关闭文件（未保存需确认）。
- **主编辑区**：
  - 当前是「会话视图」时：渲染官方会话 body（聊天 + 轨迹等）。
  - 当前是「文件」时：渲染 Monaco 编辑器（常驻，不再挂在会话 tab 环里）。
- **空态**：无会话且无文件时，显示「新建会话 / 打开项目」引导。

### 4.4 次侧栏（secondary-panel）

- 复用官方 `details` slot：工具详情、轨迹视图。
- 由会话内操作（如查看某次工具调用详情）触发显隐，右侧抽屉式。

### 4.5 底部面板（bottom-panel）

- 三个 tab：**终端 / 待办 / 队列**，复用官方 dock 内容。
- 终端：复用 `dsh-terminal`；待办/队列：复用官方 `conversation.input.dock` 的待办/队列条目。

### 4.6 状态栏（status-bar）

- 左下：连接状态（已连接 / 重连中，绿/琥珀点）+ 当前项目路径。
- 右下：当前模型名、当前会话运行态（运行中 / 空闲）、后台任务数。

## 5. 会话管理动词（收拢到列表条目）

> 这是本次设计的**核心交互变更**：以下动词全部从右上角 header 移除，收进会话列表条目的右键菜单，与「重命名/分支/归档」同级。

| 动词 | 触发方式 | 行为 | 确认 | 状态反馈 |
|---|---|---|---|---|
| 重命名 | 右键菜单 | 行内输入或弹窗改标题 | 无 | 标题即时更新 |
| 分支（fork） | 右键菜单 | 从最后完成轮派生子会话并打开 | 无 | 新会话 tab 打开 |
| 归档 | 右键菜单 | 移入归档集（隐藏，不删） | 无 | 行从列表消失 |
| 保存日志 | 右键菜单 | 原生「保存」对话框 → 写 ZIP | 无 | 结果弹窗（路径/错误） |
| **删除** | 右键菜单 | 原生「确认删除」对话框 → 物理删除 | **强制**（不可逆） | 删除中 → 成功/失败；成功后列表实时消失 |

- **删除的交互红线**：必须经过原生确认对话框（`showMessageBox`，默认「取消」），删除中显示进行态，失败保留会话并提示重试。
- **删除当前会话**：删除成功后，自动切换到最近会话或空态，不留僵尸选中。
- **入口唯一性**：右上角 header 不再有「保存/删除」按钮；「导入会话日志」保留在设置页。

## 6. 会话作为 tab 的心智模型（单一 active）

- **tab = 打开过的会话集合**（UI 态，可持久化到本地），**active = 当前会话**（对应官方 `sessions.current`）。
- 打开会话 → 新增一个 tab 并激活；切换 tab → 切换 active；关闭 tab → 移出集合（**不删会话**）。
- 空白会话（New Session）也是 tab；子代理（subagent）以面包屑/层级呈现，不另开 tab。
- 会话 tab 标题 = 会话标题（无标题则项目 basename / session id 兜底）。

## 7. 主题系统（深色 / 浅色，必须）

> **硬性要求：所有设计稿必须交付「深色」和「浅色」两套，缺一不可。**

- **机制**：语义化 CSS token（沿用官方 `--dsw-alias-*` 体系），组件只引用 token，不写死颜色。
- **切换**：顶部设置 → 外观，或状态栏快捷切换；三态 `light / dark / system`（跟随系统）。
- **必须覆盖的 token 类别**（设计稿需定义两套 hex 值）：
  - 背景层：`bg-base` / `bg-layer-1/2/3` / `bg-overlay` / `bg-skeleton`
  - 文字层级：`label-primary` / `label-secondary` / `label-tertiary` / `label-dimmed`
  - 品牌色：`brand-primary` / `brand-text`（+ 对应 invert）
  - 状态色：`state-error` / `state-success` / `state-warn`（各 primary/secondary）
  - 交互态：`interactive-bg-hover` / `interactive-bg-active` / 边框 `border-l1/l2/l3`
  - 特殊：`markdown-code-block` / `markdown-inline-code`（代码块在深浅色下对比度要够）
- **深浅色对比度基线**：正文 ≥ 4.5:1，大号文字 ≥ 3:1；代码块背景与正文背景要有明显层次。
- **Monaco 主题**：编辑器用 `vs-dark`（深色）/ `vs` 或 `vs-light`（浅色），与全局主题联动。

1. **双主题**：深色 + 浅色各一套（§7），或一套 + 明确 token 映射表（推荐后者）。

5. **交互标注**：右键菜单、tab 关闭、拖拽、主题切换等关键交互需标注行为。
