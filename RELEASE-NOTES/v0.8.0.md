**应用版本 `0.8.0`** · 底座 DeepSeek Harness `0.2.1-rc.3`

> 本版是**基座升级版**：底层 DeepSeek Harness 从 `0.1.5-rc.3` 升级到 `0.2.1-rc.3`，带来官方新能力与行为变化的同时，修了一批用户报障。

## TOP5 更新日志

1. **Windows · 工作区在管理员属主目录下完全不可用（本版最重要）**：如果你的工作区目录曾被管理员账号创建/接管（比如装过软件、跑过提权脚本），目录属主变成了 Administrator，普通用户没有写权限 —— 于是终端打不开、Agent 跑不了、整个工作区「死掉」。本版新增 **UAC 提权 helper**：检测到属主不匹配时弹引导卡，一键提权修复 ACL（`takeown` + `icacls`），实机端到端验穿。这是 Windows 独有缺陷，macOS / Linux 不受影响。

2. **子 Agent 胶囊点击跳转后消失**：会话条里的子 Agent 胶囊排，点进去看子会话、再返回父会话时，已完成的 Agent 胶囊不再显示 —— 看起来像「凭空消失」。根因是胶囊排读了一个不稳定的投影键，改成读官方投影存储后稳定保持。

3. **配置向导重复供应商静默覆盖**：在配置向导里添加一个已经配过的供应商（比如已配过深度求索官方，再从目录选「深度求索」），旧版本会**静默覆盖已有配置**。本版加了重复供应商保护：已配置的会提示确认、同品牌族内有标记、自定义 route 占用时拦截。

4. **API Key 占位符显示 `[object Object]`**：配置向导里 API Key 输入框的占位符（灰色提示文字）在某些供应商下显示成 `[object Object]` 而不是供应商名称。根因是占位符走了对象直转字符串，改为走本地化渲染后正常显示供应商名。

5. **task agent 审批「不可用」**：在无界面附着的会话（task agent）里收到审批请求时，审批被标记为 `unavailable` 并 deny —— 子 Agent 永远等不到审批结果。根因是审批转发载荷缺 `sessionId`，补上后审批可正常转发与执行。

## 注意事项

### 用户须知

- **Windows 资产未签名**：首次运行安装器会被 SmartScreen 拦截 —— 点「更多信息」→「仍要运行」即可。这是预期行为，不是病毒告警。
- **Windows · DPAPI 凭据**：Windows 版的 API Key 等凭据走 DPAPI 加密，绑定当前系统用户。**重装系统或换用户账户后旧凭据不可解密，需重新录入 API Key**。在同一用户下升级不受影响。
- **Windows / Linux 暂无托盘**：关闭主窗口即退出应用（托盘仅在 macOS 提供）。macOS 关窗为隐藏到菜单栏。
- **Windows 按用户安装**：默认装到当前用户目录，不需要管理员权限。
- **工作区在管理员属主目录下的用户**：升级到本版后首次遇到该问题时会看到引导卡，按提示提权即可。此前已遇到此问题的用户升级后也会自动检测并修复。
- **Linux / macOS 差异**：本版的 Windows ACL 提权修复与 DPAPI 凭据是 Windows 独有；Linux 凭据走密钥环（gnome-libsecret）、macOS 走钥匙串，不受上述问题影响。三平台门禁覆盖 macOS 与 Windows 真机验证，Linux 侧按机制判定无需迁移但未在 Linux 真机上额外验证。

### 开发约束

- **基座升级 0.1.5-rc.3 → 0.2.1-rc.3**：官方 dsh 全量升级，fork 四包（`corum-ui-trajectory` / `corum-ui-model-ask` / `corum-ui-base` / `corum-ide-ui`）适配 rc3 的 API 变化。运行期 bundle 机制是本 fork 的在用核心机制，刻意保留未移除。
- **guard §17 rc3 断言**：`verify-refactor-guard` 吸收了 rc3 线 9 个净增 RPC 进冻结基线，HEAD 对照去重。
- **`disabled` patch 不可过滤**：boot() 层栈里的 `disabled` 行承担双重职责（索引标记 + 抑制官方包让 fork 顶替），不可用 `.filter(p => p.disabled !== true)` 过滤——会同时激活官方与 fork 包导致 `service has been registered` 冲突退出。
- **Windows 提权 helper 的 PowerShell 转义**：`takeown` / `icacls` 命令走 PowerShell 单引号串，不可在单引号串内加倍双引号（会导致路径畸形）；`schtasks` 宿主进程的 PATH 缺失 PowerShell，必须用绝对路径 `powershell.exe`。
