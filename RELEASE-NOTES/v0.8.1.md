**应用版本 `0.8.1`** · 底座 DeepSeek Harness `0.2.1-rc.3`

> 本版是**缺陷修复版**，核心是用户报障的三个界面/联动问题，外加一批 MCP 连接可靠性与跨平台测试的收口。

## 用户报障修复

1. **右侧编辑器与资源管理器不跟随当前会话（本版最重要）**
   在 A 工作区的会话里对话，右侧显示的却是 B 工作区的内容——具体到本次报障：在 `kkc-desktop` 对话，右侧却显示 `pendiji` 的项目。

   根因：判断「当前会话」时读了一个**在当前底座版本里根本不存在的字段**（`sessions.list` 快照没有 `current`）。读不到就静默回落到工作区列表的第一项，而那个列表按**创建时间倒序**排列 —— 于是永远显示「最新创建的那个工作区」，与你在跟谁对话毫无关系。

   本版改为从会话选择源读取真实当前会话，并按「会话 cwd → 所属工作区」的顺序解析；**没有选中会话时显示空态**，不再随便挑一个工作区充数。

2. **切换会话时分栏不自动关闭**
   侧栏分栏（右栏）承载的是**上一个会话上下文里的东西**（子 Agent 会话、双栏对读）。切到别的会话后它既不代表新上下文、也没有可推导的对应物，却继续留在那里冒充当前会话的侧栏。

   本版按你的口径改为：**切换会话即收起分栏**，让你在新会话里重新触发。判定用「会话选择真的变了」而不是「收到一次广播」——避免同值写入把刚打开的分栏立刻收掉。

3. **助手正文里的链接点了没作用**
   Agent 总结里的文档链接（本地文件或外部网址）点了没反应。

   根因有两层：助手正文的 Markdown 渲染**没有接上链接委派**，本地文件链接会直接退化成纯文本；外链则走浏览器原生跳转，而桌面壳不处理新窗口请求 —— 于是点击被静默丢弃，既不跳转也不报错。

   本版接上了链接委派：
   - **本地文件链接**点击即在右侧编辑器打开，带 `#L12` 形式时**定位到该行**；
   - **外链**交给系统默认浏览器（只放行 http/https，其余 scheme 提前拦下）。

## 连接可靠性

4. **MCP 服务崩溃后可能一直连不回来**
   修了两处竞态，症状是「崩溃那一次调用成功了，下一次调用却报 `Connection closed`」：
   - 建连期间子进程就退出时，连接池会把一条**已经死掉**的连接当作正常的保存下来；
   - 连接在「刚拿到、还没用」的间隙死掉时，错误直接抛给调用方，池仍抱着死连接。

   现在遇到连接关闭会**复位并重连一次**（只一次，不无限重试）；工具自身失败、参数错误、超时等其它错误**原样抛出**，不会被重连掩盖。

5. **提炼任务的磁盘读回竞态**
   提炼任务落盘在 `finally`，而读回测试只等「文件出现」不等「内容写完」，两者竞态会导致读到旧内容。改为等内容到位（判据是内容而非文件存在）。

## 跨平台

6. **Windows 上若干测试的隐式平台假设**
   这批不是产品缺陷，而是测试里写死了 POSIX 假设（只设 `HOME` 而 Windows 读 `USERPROFILE`、用 `URL.pathname` 拼路径导致 `D:\D:\...`、断言 POSIX 分隔符、断言 POSIX 可执行位）。已在 **win10 真机逐条验证根因**后修正，三平台断言各自表达同样的语义。

## 验证

- CI 三道检查全绿：`gate` / `platform-tests (macos)` / `platform-tests (windows)` —— 这是自 11-20（#234）以来首次全绿。
- 三个用户报障均在真实实例上验穿：编辑器根跟随（自动化用例 14/14 通过）、链接定位到第 12 行、外链点击被接管且零新增控制台错误。
- 单测：全 workspace 串行通过。

## 注意事项

- 本版**未**改动会话存储格式、配置格式或任何对外契约，可直接覆盖升级。
- 应用内的「侧栏分栏」在切换会话后会自动收起，这是本版的有意行为（见上第 2 条），不是功能丢失。
