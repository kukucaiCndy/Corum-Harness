**应用版本 `0.8.3`** · 底座 DeepSeek Harness `0.2.1-rc.3`

> **这是针对 0.8.2 的紧急修复版。0.8.2 装好后应用等于打不开，请务必升级。**

## 你可能会遇到的两个问题（都已修复）

### 1. 0.8.2 装好后，界面一直停在启动页

打开应用，看到一个加载动画，然后就一直等下去；约 30 秒后提示「启动失败：主界面加载超时」。

实际上后台是起来了的，是**界面层**没挂起来。日志里是这一句：

```
web boot: 11 entries did not activate
@corum/corum-ui-conversation: import failed: client-modules:
  require("@corum/corum-agent/contract") missed the module table
```

根因是打包流程里的一个**静默降级**：

- 仓库里有一处循环依赖（会话层 ↔ Agent 层），从零构建时会先剪断其中一条边;
- 于是「会话层」在「Agent 层」产出它要内联的那个模块**之前**就完成了构建;
- 打包工具解析不到，就把它降级成了一条运行时找不到的外部引用 —— 而这**只报一条警告，退出码仍然是 0**;
- 原有的构建检查（文件在不在、大小是否正常、样式有没有内联）全部通过，坏包就这么发出去了。

本版两处修复：从零构建时对环上的会话层包**重建一次**（此时依赖必然已就位）；并新增一道**按产物内容**的检查 —— 任何解析不到的运行时引用都会让构建和打包**当场失败**，绝不再留到用户启动时才发现。

### 2. macOS 上升级后提示「Corum 已损坏，无法打开。你应该将它移到废纸篓。」

文件没有损坏。这是 macOS 的隔离机制 + 本应用没有苹果开发者签名叠加的结果：

- 更新包从网络下载时，系统会打上「来自网络」的隔离标记;
- 解压它会把标记**复制到新版本的每一个文件**上（0.8.2 的包里有 2.8 万个）;
- 本应用没有苹果开发者签名（ad-hoc 签名），系统无法验证来源，于是拒绝启动。

实测对照：同一份包，带标记时用 `open` 启动失败；`xattr -cr` 清掉标记后立刻正常。

本版让应用内更新在**替换完成、重启之前**主动清掉该标记。

> **已经装了 0.8.2 且被拦住的用户**：升级到 0.8.3 时如果仍然被拦截，说明当前运行的那个版本还没有这段修复，请手动执行一次
> ```
> xattr -cr /Applications/Corum.app
> ```
> 或直接从 Release 页面重新下载安装包。

## 顺带修好的

- **一道静默失效了两个月的打包检查。**「UI 插件样式是否已内联」的检查原先按「包目录里有没有 `scripts/inline-css.mjs`」筛选，而那批逐包脚本早已收敛成一个共用命令行工具，磁盘上一个都不剩 —— 于是它匹配到 0 个包、循环体从不执行、每次都打印「通过」。这道检查因此从未真正检查过任何东西。现在改为按「包是否声明了客户端入口」判定，扫描面从 0 个包变成 34 个。
- **构建/打包检查本身进了 CI。** `scripts/lib` 下的回归测试不属于任何 workspace 包，原先的 `pnpm -r run test` 扫不到它们；现在在两个门禁 job 里各显式跑一遍。
- **macOS 更新安装脚本的生成逻辑抽成纯函数**并补了 8 条测试 —— 这段逻辑原先只能在真机上装一遍才能发现问题（0.8.2 正是这么漏出去的）。

## 升级建议

**所有人**建议升级到 0.8.3，尤其是已经装了 0.8.2 的用户。

如果升级后应用起不来：

1. macOS 提示「已损坏」→ 先按上面的 `xattr -cr` 处理;
2. 界面停在启动页 → 说明跑的是旧版本，请确认应用版本号是 `0.8.3`（左下角／关于面板）。
