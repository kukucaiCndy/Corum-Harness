# v0.8.4 · 修复 Windows 工作区权限死循环 + Git 面板

**应用版本 `0.8.4`** · 底座 DeepSeek Harness `0.2.1-rc.3`

> 如果你把项目工作区放在 **C 盘用户目录之外**（D 盘 / E 盘等数据盘），并且每次让 Agent 做事都弹「工作区目录权限不足，需要管理员权限一键修复」——点了一键修复，下个项目照样弹——这一版修的就是它。

## 你会遇到的问题（已修复）

### 1. Windows：工作区在 D/E 盘时，「一键修复」反复弹、点了也修不好

**现象**：在数据盘上的项目里让 Agent 做事，弹「工作区目录权限不足，需要管理员权限一键修复」。点「一键修复」可能弹 UAC，也可能什么都不发生；换一个新项目，仍然弹。同一台机器上个别老项目却不弹（通常是手工处理过权限的那些）。

**根因（两层叠加）**：

- Windows 对非系统盘的根目录默认只给普通用户 **Modify** 权限，而 Modify **不含修改 ACL 所需的 WRITE_DAC**——这不是权限被谁破坏了，是系统默认配置。放在 `C:\Users\<你>\` 下的工作区天然对你有完全控制，所以那些用户从不出问题；
- 而自动修复流程把「递归取得所有权」（`takeown /r`）放在了**必经路径**上：只要目录树里有任何一个外账户文件（安装器写的、别的管理员建的、某些 node_modules），它就失败；失败后回落的命令在普通权限下必然失败——于是流程在**真正有效的那条修复命令执行之前**就判定「需要管理员」，弹出了引导你去开 UAC 的弹窗。而那条命令（给当前用户补一条可继承的完全控制权限）**根本不需要管理员**。

**修法**：

- 修复流程反转：**先**只补一条可继承的完全控制权限（`icacls /grant <你>:(OI)(CI)F`，普通权限、不递归、不碰属主），成功即结束；失败才走所有权路线，也只有那时才需要递归；
- 弹窗文案按实际检测结果分叉：属主真的不是当前用户才提示「需要提权修改属主」；其余情况提示查看日志里的诊断信息，不再一律误导你去开管理员权限；
- 每条修复命令的真实执行结果（退出码 + stderr）写进 host 日志，排障不再靠猜。

**已遇到弹窗的用户**：升级到本版后，多数场景下弹窗直接消失。若个别目录仍弹（属主确实不是你），点「一键修复」即可（这回是真需要提权的那种）。

### 2. 「计划」卡片点不开

点助手输出的计划卡片没有反应。根因是界面外壳缺失了一个面板槽声明，同时计划卡片改为在**原位内联展开**，不再依赖侧栏。

## 新增：Git 面板

对话输入框工具栏新增 **git 按钮**，向上展开玻璃面板：

- **三态**：空闲时可操作 / 提交后显示结果与注入预览 / Agent 工作中全置灰防误触；
- 切分支与手动提交在**你下一轮发消息时**一次性注入给 Agent，提交信息按规则拼接、不额外调用模型；
- 提交范围限定到你勾选的文件，重命名与删除正确处理；未提交项显示语义状态字符（不再是 git 原始码 `??`）。

## 其他修复

- 换模型后采纳该模型的默认思考档，不再沿用上一个模型的档位；
- 上下文压缩收窄输出预留，降低撞配额上限的概率；
- 子 Agent 续跑终态为失败时不再当作成功上报；
- Windows 打包：平台绑定校正对本机打包不再跳过，产物级补上闭包绑定断言。
