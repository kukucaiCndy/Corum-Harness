**应用版本 `0.8.2`** · 底座 DeepSeek Harness `0.2.1-rc.3`

> 本版是**更新功能本身的修复**：让 macOS / Windows 能真正用上「应用内一键更新」，并修好更新面板里的更新日志与实际不符的问题。都是你装上 0.8.1 后会直接撞上的两个问题。

## 修复

### 1. macOS / Windows 的应用内自动安装恢复可用

你装上 0.8.1 之后，如果哪天有新版本，点「检查更新」下载完，面板会显示：

> 这一形态（系统包 / deb）不能应用内安装：请用系统包管理器安装下载好的包

按钮是灰的。**但这是错的**：你用的是 macOS，根本没有 deb。

根因是一行**不看平台**的判定，只认 Linux 的 `.AppImage` 资产。macOS 下载的是 `.zip`、Windows 下载的是 `.exe`，两者都被判成「不可安装」。而底层的安装实现（macOS 解压替换 `.app`、Windows NSIS 静默安装）一直是完整的，只是永远等不到调用。

本版按平台各自判定资产形态，点「重启安装」就能自动完成。

### 2. 不能自动安装时，明确告诉你在哪、怎么装

Linux 的 `.deb` 确实不能应用内安装（`/opt` 属 root，原地替换不了）—— 这是真实限制，保留。

但原来的文案只说「请用系统包管理器安装下载好的包」，**既没告诉你文件在哪个目录，也没给命令**，而更新包通常落在 `~/.corum/updates/` 这种平时不会去翻的地方。

本版新增：

- **「打开所在目录」按钮** —— 直接在系统文件管理器里揭示那个包；
- **可照抄的安装命令** + 你机器上的包的绝对路径（例如 `sudo dpkg -i "/home/you/.corum/updates/…deb"`）。

### 3. 更新日志显示的是上一个版本的内容

打开「检查更新」看到的是 v0.7.0 （10-23）那一节，不是当前版本该有的。

两层原因：

- 这份随包分发的日志文件**自 v0.7.0 之后就没再追加过**（v0.8.0 / v0.8.1 两次发版都漏了）；
- 面板按当前版本找对应节，找不到就回落到最新一节 —— 所以你看到的是 v0.7.0。

现已补齐 v0.8.0 与 v0.8.1 两节，并**在发版脚本里加了门禁**：目标版本的节缺失、或两份副本内容不一致时，发版直接失败。这个疏漏不会再发生。

> 顺带说明一个机制细节：这个文件有两份副本（仓库根一份、随包一份），运行时读的是随包那份，两者不是硬链接。只改仓库根那份不会生效 —— 门禁现在强制两者一致。

## 注意事项

- **macOS 的自动安装是首次真正可用**。`installDarwin()` 这套逻辑此前从未被调用过（一直被上面那行判定挡着）。我验证了面板判定、按钮可用与单测，但**没有实际点「重启安装」去替换 `/Applications/Corum.app`**（那会重启正在使用的实例）。所以「解压 → 替换 → 重启」这条全链在真实环境下的首次验证，会发生在你下一次点它的时候。如果届时失败，请把面板上的错误信息发我。
- 本版**未**改动会话存储格式、配置格式或任何对外契约，可直接覆盖升级。
